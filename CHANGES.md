# Изменения относительно коммита ff3661b

Правки, чтобы проект можно было безопасно запустить на сервере с HestiaCP.

## 1. Веб-админка: порт 8080 → 3080

На сервере порт 8080 занят Apache (бэкенд HestiaCP, через него nginx отдаёт сайты).
С `"8080:8080"` контейнер не запускался, а после перезагрузки мог занять порт раньше
Apache и положить сайты.

`docker-compose.yml`: `"3080:8080/tcp"`. Внутри контейнера админка по-прежнему на 8080.

## 2. DNS отвечает только разрешённым клиентам

Docker публикует порты через NAT в обход файрвола HestiaCP, поэтому порт 53 открыт
всему интернету, что бы ни было настроено в Hestia. Без ограничений это открытый
DNS-резолвер: его используют для DDoS-атак, а IP сервера попадает в блэклисты.

`conf/AdGuardHome.yaml`, секция `dns`:

```yaml
allowed_clients:
  - 127.0.0.1
disallowed_clients: []
```

По умолчанию DNS не отвечает никому снаружи. Свои IP нужно добавить в админке:
**Настройки → Настройки DNS → Настройки доступа → Разрешённые клиенты**.
Когда IP телефона сменится, его нужно поправить там же.

## 3. Ротация логов Docker

В `docker-compose.yml` добавлено ограничение: не больше 3 файлов по 10 МБ.

## 4. Тексты

В `deploy.sh` и `README.md` исправлены порт и подсказки. Совет открыть 53 и 8080
в файрволе Hestia удалён: он не нужен (Docker обходит файрвол) и опасен.

## На заметку: память

Четыре списка дают около 1,1 млн правил (только `gambling.txt` даёт 675 тыс.).
При загрузке и ежедневном обновлении списков AdGuard занимает до ~230 МБ при лимите
256 МБ, в простое ~145 МБ. Если лимита не хватит, контейнер перезапустится сам.
Варианты: поднять `memory` до 384M или убрать самый большой список.
